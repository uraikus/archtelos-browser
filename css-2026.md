# CSS: what the style engine implements, against the 2026 snapshot

The target is the **[CSS Snapshot 2026](https://www.w3.org/TR/css-2026/)**
(CLAUDE.md, §2). The snapshot sorts specifications into four classes;
this file takes them in its order and states, for each, what the engine
does. The work it implies is in [todo.md](todo.md).

**The engine column is read from the code**, not from the other
documents: all of `src/css/`, plus the places `src/layout/layout.f` and
`src/paint/paint.f` consume a computed value. A property the cascade
computes but neither reads counts as absent, because a page renders the
same either way. Nothing is excluded by it now: `overflow` was, until
the painter began clipping by it.

`www.w3.org` is refused by this network's egress policy — the proxy's
CONNECT is answered 403 — so the snapshot has to be supplied to a
session rather than fetched, as it was for this one.

## The headline

The official definition of CSS is 24 specifications. **The engine
implements no part of 2 of them** and part of the other 22, two of those
completely — Namespaces 3 and Conditional 3. The two it does not touch
are the two it cannot: **Compositing and Blending 1** needs a
compositing operator, and the runtime sets `CAIRO_OPERATOR_SOURCE` at
every draw with no call to change it; **Easing 1** describes the timing
functions of transitions and animations, which need a clock and a
repaint loop rather than a property.

Of the three lower classes, Grid is substantially implemented, Selectors
4's functional pseudo-classes are, Fragmentation 3 has the break
controls a column context can act on, Masking 1 has `clip-path`, Shapes 1 has `shape-outside`, and Transforms 2 and Containment 2
have the parts that are not three-dimensional or dependent on knowing
what is on screen. `@layer` orders the cascade, and Color 5 is
both of its features.

Three runners in `tests/conformance/` put numbers on it, and each is a
floor the suite will not let drop:

| Measure | Now |
|---|---|
| CSS properties that change what renders, of the 369 the instrument can grade | **186** |
| HTML elements whose default `display` matches Chromium's, of 122 | **122** |
| CSS selectors matching the same elements as Chromium, of 61 | **61** |

The property count uses the same rule as this file: a property the
cascade computes but neither layout nor paint reads is not implemented,
because the page renders the same either way. `overflow` is what
still falls to it.

## 1. The official definition

Everything here is stable, and the snapshot's own framing is that this
is CSS "in its most complete form". The gaps in this table are the ones
that matter first.

| Specification | Engine |
|---|---|
| **CSS Level 2** | The bulk of what works: normal flow with margin collapsing, inline formatting and line boxes, table layout (§17) in both algorithms — automatic, and the fixed one that takes its column widths from the first row and never measures a cell's content — with `caption-side` and `empty-cells`, list markers inside or outside the box, and **positioning** (§9.3) — `relative` offsets a box and its descendants without disturbing the flow, `absolute` and `fixed` leave the flow and resolve against the nearest positioned ancestor or the viewport, all four inset properties work, and `z-index` orders positioned siblings. **Floats** (§9.5) work too: a float is placed at the edge of its containing block after any float already there, the line boxes beside it are shortened so text wraps around it, a block box's own position and width ignore it, and `clear` moves a box below the floats on a side. **Generated content** (§12) works: `::before` and `::after` generate boxes from `content`, which takes strings, `attr()`, `counter()`, `counters()` and the four quote keywords, and `counter-reset` and `counter-increment` maintain counters with the standard's scoping — an instance is in force for the element that reset it, its descendants and its following siblings. `quotes` gives the strings for `open-quote` and `close-quote`, at a depth that runs over the whole document in document order rather than following element nesting, repeating the last pair past the end of the list; `<q>` gets a pair from the user-agent stylesheet. `url()` in `content` does not exist, and a counter is always rendered in decimal. **`overflow: hidden`** clips a box's descendants to its padding box, painted through an offscreen image because the canvas has no clip region — and inside such a subtree a `border-radius` is drawn square, because an image has no path API (FINDINGS.md). `::first-letter` (§5.12.2) styles the first letter of a block's first line, taking preceding punctuation with it and skipping leading whitespace. `clip` (§11.1.2) cuts an absolutely positioned box to a rectangle, through the same machinery as `clip-path`. `orphans` and `widows` (§13.3.1) constrain where a paragraph may be broken; there are no pages here, so they act where the only fragmented context is, between the columns of a multi-column container. Missing from CSS2 itself are `overflow: scroll` and `auto`, which need a scrollable area rather than only a clip, `::first-line`, `url()` in `content`, and the rest of **paged media** (§13). A margin that collapses all the way through to the root is dropped rather than moving the document down |
| **CSS Syntax 3** | Partial, and not by this algorithm. There is no tokenizer in the standard's sense: parsing is index scanning. Comment stripping runs first and is not string-aware, so `/*` inside a string or `url()` opens a comment. Escapes are accepted in identifiers and never decoded, so `.a\.b` can never match. No `<!--`/`-->` |
| **CSS Style Attributes** | Yes. The `style` attribute is parsed per element, though it is treated as an origin above author rules rather than as a specificity |
| **Media Queries 3** | Every feature the level defines, in the boolean form as well as with a value: `width`, `height`, `device-width`, `device-height` and their `min-` and `max-` forms; `orientation`; `aspect-ratio` and `device-aspect-ratio`, compared as two whole numbers rather than two divisions, so 800 by 600 is `4/3` exactly; `color`, `color-index` and `monochrome`, which say eight bits a component, no colour table and not monochrome; `resolution` in `dpi`, `dpcm`, `dppx` and `x`, which says 96 to the inch; and `grid` and `scan`, which describe devices this is not. What it calls the device is its own window: there are no screen metrics to ask for, and a page asking about the device is deciding whether it is on a phone, which the window size answers as well as the screen does. `hover` and `pointer` answer `hover` and `fine`, because this browser opens a window with a pointer in it — headless Chromium answers `none`, which is a fact about that process rather than about the standard. The remaining gap is time rather than features: a query is evaluated when the sheet is parsed, so resizing the window does not re-evaluate it |
| **CSS Conditional 3** | Both. `@supports` evaluates its condition: a declaration is supported when the property is one the cascade computes and the value uses no function the engine cannot resolve. `not`, `and`, `or` and nesting are handled; `selector()` reports unsupported. The list of properties it answers from is checked against the property instrument on every run: a property that changes what renders and is not on the list, or is on the list and changes nothing, fails the suite, because a hand-written list beside a measurement drifts from it in both directions and silently |
| **Selectors 3** | Every selector this can measure, it gets right: all 61 entries in `tests/conformance/css-selectors.txt` match exactly the elements Chromium matches. Type, `*`, `#id`, `.class`, all six attribute operators, all four combinators, the full `An+B` grammar in `:nth-child()`, `:nth-last-child()`, `:nth-of-type()` and `:nth-last-of-type()`, the `first`/`last`/`only` child and of-type pseudo-classes, `:root`, `:empty`, `:link`, `:enabled`, `:disabled`, `:checked`, `:lang()`, and `:not()` with one compound. A rule whose selector list contains anything unparseable is dropped whole, as §4 requires. `:target` parses and matches nothing, which is right for a document never navigated to a fragment. **`::before` and `::after` generate boxes**, in both the one- and two-colon spellings; `::first-line` and `::first-letter` do not, and make their rule unusable rather than silently matching the element |
| **CSS Namespaces 3** | All of it. `@namespace` binds a prefix, or a default namespace when it names none, and a selector's namespace part is honoured: `ns|E` for a declared prefix, `*|E` for any namespace, `|E` for no namespace, and a bare `E` for any namespace until a default is declared and then only that one. A prefix nobody declared makes the selector invalid, so it matches nothing rather than being read as a type. Every element in an HTML document is in the XHTML namespace, so all of this comes down to one string comparison — which is also why the whole specification can be honoured rather than approximated |
| **CSS Cascade 4** | Substantially. Specificity is the triple (ids, classes and attributes and pseudo-classes, types), packed base 1024 so that an integer comparison is the lexicographic one. Importance inverts the origin order, so an important user-agent declaration outranks an important author one. `inherit` takes the parent's computed value, `initial` the initial value, and `unset` whichever of the two the property calls for. Missing: `revert`, which needs the origins kept apart after the cascade and behaves as `unset`, and `all` |
| **CSS Values and Units 3** | Partial. Units: unitless, `px`, `%`, `em`, `rem`, `pt`, `pc`, `in`, `cm`, `mm`, `ex`, `ch`, `vw`, `vh`, `vmin`, `vmax`. Missing `q`, and all angle, time, frequency and resolution units. `calc()` is implemented: a sum of products over lengths and plain numbers, with nested parentheses and nested `calc()`, and a result that carries a pixel part and a percentage part separately so `calc(100% - 2em)` waits for the containing block. The standard's invalid cases are rejected, among them a `-` without spaces around it and a length added to a number. `attr()` is missing. `rem` multiplies the root element's computed font size and `vh` the real viewport height |
| **CSS Custom Properties 1** | Yes. Custom properties are kept, inherit, and `var(--name, fallback)` substitutes them wherever a value is read, including inside another custom property. An unresolvable `var()` with no fallback makes the declaration invalid rather than empty, as the standard requires. A vendor prefix is still dropped |
| **CSS Box Model 3** | Yes, in substance: all four margins and paddings, and margin collapsing, which CSS2 §8.3.1 still owns |
| **CSS Color 4** | Substantially: `transparent`, `currentcolor`, all four hex forms, `rgb()`, `rgba()`, `hsl()`, `hsla()` with either separator and alpha, all 148 named colors, all nineteen system colors, `opacity`, and the wider color spaces — `hwb()`, `lab()`, `lch()`, `oklab()`, `oklch()` and `color()` over `srgb`, `srgb-linear`, `display-p3`, `a98-rgb`, `prophoto-rgb`, `rec2020`, `xyz`, `xyz-d65` and `xyz-d50` — each with `none` components, percentages on the standard's own scales, a hue in degrees, radians, gradians or turns, and a slash alpha. They resolve to a packed sRGB integer through the standard's conversion matrices, clamped per channel where the color falls outside the sRGB gamut rather than gamut-mapped, which is what Chromium paints for these colors too. No `<color>` interpolation, since nothing here animates. `opacity` is not inherited: its computed value is the element's own, and a separate accumulated value carries group opacity to the painter, which approximates it rather than compositing a layer. The color syntax is graded by tests/unit/test_color4.f, whose expected pixels were derived twice over — from the standard's §17 pseudocode in a separate script, and from the pixel headless Chromium paints — because the property instrument counts `color` as implemented whatever syntax reaches it |
| **CSS Backgrounds and Borders 3** | Partial: `background-color`, a `background-image` from `url()` or a gradient, `background-repeat` in all five forms, `background-position` with keywords, lengths and percentages on both axes, `background-size` with `cover`, `contain`, lengths, percentages and `auto`, and `background-origin` and `background-clip` over all three box edges, per-side border width, style and color, the `border` shorthands, and `border-radius`. A background image is fetched after the cascade, since the URL only exists once styles are computed, and a tile that runs off the box is cut off there. every border style paints as itself, per side: `solid`, `dashed`, `dotted`, `double` — whose two lines and gap are each as near a third of the width as it allows — and `groove`, `ridge`, `inset` and `outset`, which shade an edge against its opposite, the two shades being the border colour and half its brightness, since the standard fixes only that they are based on it. `border-radius` sets each corner separately — the shorthand's one to four values, the four `border-*-radius` longhands and the four logical corner names — in px, with no percentage and no elliptical form, the `/` form's vertical radii being read as the horizontal ones. `box-shadow` casts outer and `inset` shadows with offset, blur, spread and a list of shadows, the blur approximated by nested rectangles whose alpha accumulates, since the canvas has no blur. `border-image` cuts its source into nine regions by `border-image-slice`, which takes a number or a percentage on each side and `fill` for the middle: the four corners are drawn at the border's own size, the four edges fill what the corners leave, stretched or tiled by `border-image-repeat`, and `border-image-width` and `border-image-outset` move and resize the area they go in. `round` and `space` tile as `repeat` does, differing only in how the last tile is fitted. Each region is cut by blitting the source into a blank image at a negative offset, because an image destination has no source-rectangle `drawImage` (FINDINGS.md) and a border image inside a clipped subtree is painting into one. `background-attachment: fixed` positions the image against the viewport rather than the element, so it stays put while the page scrolls under it, clipped to the element as always; it says nothing about a background colour, which fills its box either way. No layers (one image per box); a clipped background keeps the border box's `border-radius` rather than deriving the smaller inner curve |
| **CSS Images 3** | Partial: `linear-gradient()`, `radial-gradient()` and both repeating forms as a background image. A linear gradient takes `to <side>` and `to <corner>` keywords and an angle in `deg`, `turn`, `rad` or `grad`; a radial one takes `circle` and `ellipse`, all four extent keywords, explicit radii and `at <position>`, and a degenerate ending shape renders as the last stop. Both take any number of colour stops, positioned in percentages, lengths, or omitted and spaced evenly, and both are painted as flat bands rather than by the canvas's own gradient, which cannot be called with colours that are not literals (FINDINGS.md, "a gradient cannot be built at run time"). `object-fit` in all five values and `object-position` with keywords and lengths on both axes, sized by the specification's own algorithm and clipped to the content box. Missing: `conic-gradient()`, `image()`, `image-set()`, `cross-fade()`, gradient interpolation hints, and the degenerate ellipse with zero height but non-zero width, which renders as the last stop here rather than as the mirrored linear gradient the standard names |
| **CSS Fonts 3** | Partial: `font-family`, `font-size` with the absolute and relative keywords, `font-style`, the `font` shorthand, and `font-weight` **as a boolean**. The cascade computes the weight correctly — 600 and above are bold, as CSS says — and has nowhere to put it: Festina's font weight is a two-valued Cairo enum, so 400 and 500 render identically and so do 600 and 900 (FINDINGS.md, "a font has two weights, and no way to load one"). `@font-face` is closed by the same binding, which selects a family from the system and cannot load a file. No `font-variant`, `font-feature-settings`, `font-stretch` or `unicode-range` |
| **CSS Writing Modes 3** | The bidirectional half. `direction` sets a paragraph's base level and is what `text-align`'s `start` and `end` resolve against — including the initial value, which is `start`, so an element with no side of its own follows its direction. The bidirectional algorithm (UAX #9) puts each finished line into visual order: the W, N and I rules and the L2 reordering, with character classes taken from script ranges rather than from the Unicode database, which this repository would have to vendor. Hebrew and Arabic rendered in logical order before, which is backwards on the screen. The explicit embedding and isolate codes — the X rules — are not implemented, so a document that overrides the implicit result with them gets the implicit result; `unicode-bidi: bidi-override` is honoured, `embed`, `isolate` and `plaintext` are not, and `@supports` answers no for `unicode-bidi` because it answers per property rather than per value. A line is reordered within each of its text fragments and not across two inline boxes on the same line. No `writing-mode` or `text-orientation`: a vertical axis is a second layout axis, not a property. Arabic is not shaped — the toy font API has no contextual forms — so its letters appear in isolated form in the right order |
| **CSS Multi-column 1** | Partial: `column-count` and `column-width` with the standard's used-value rule — a count alone is that count, a width alone is as many columns of at least that width as fit, and both together make the count a maximum — plus the `columns` shorthand, `column-gap`, and `column-rule` with its three longhands, painted down the middle of each gap through the same code as a border side so every style paints as itself. The content is laid out once at the column width and that single flow is then broken into columns of equal height, so nothing is laid out twice. **Breaking happens between the container's direct children and between the line boxes of a direct child, and no deeper**: a subtree nested below those children stays whole and overflows its column rather than being split. A child whose lines are split has its own box refitted to the lines that share its first column, so its background does not smear across the gap, which is an approximation of the fragment boxes the standard would make. `column-span: all` takes a direct child out of the columns and lays it across every one of them, splitting the container into the run before it, the spanner at the full width, and the run after, each balanced on its own. Only a direct child can span: the standard lets a spanner sit deeper and breaks its ancestors around it, which needs the fragment boxes below. No `column-fill: auto`. Where a column breaks is under the control of CSS Fragmentation 3's `break-before`, `break-after` and `break-inside` and of CSS2's `orphans` and `widows`, which are read per column: a break inside a paragraph has to leave `orphans` lines behind it and take `widows` with it, and when the two cannot both be honoured — five and five of six lines — widows is the one dropped, which is what Chromium does |
| **CSS Flexible Box 1** | Most of it. `display: flex` and `display: inline-flex` both establish a flex container, and an inline-flex one is inline-level and shrinks to fit; `flex-direction` takes all four values and `flex-wrap` all three, with the `flex-flow` shorthand; `order` reorders the items; `flex-grow`, `flex-shrink` and `flex-basis` distribute the free space of their own line (with the `flex` shorthand, including its `initial`, `auto` and `none` keywords, and the rule that a bare `flex: 1` zeroes the basis so the whole line is shared rather than the slack); `justify-content` takes all six values; `align-items` and `align-self` take `stretch`, `flex-start`, `flex-end`, `center` and `baseline`, with the Box Alignment 3 synonyms `start`, `end`, `left`, `right` and `normal`; `align-content` distributes the lines across the cross axis and stretches them when it is not asked otherwise; an auto margin absorbs a line's free space before `justify-content` is consulted. `gap`, `row-gap` and `column-gap` separate items on a line and the lines from each other. Missing: `flex-basis: content`, the min-content floor that stops an item shrinking below its own content, and nested flex containers as flex items |
| **CSS Basic User Interface 3** | `outline` only, with its longhands: drawn just outside the border box, taking no space, and painted through the same code as a border side, so every style paints as itself — `none` draws nothing however wide it is asked to be, and a style with no width takes `medium`, and `outline-offset` moves it away from the border box and leaves the gap empty. `text-overflow: ellipsis` cuts a line that runs out of a clipping box back to an ellipsis, one character at a time until it fits. `pointer-events: none` takes a box out of hit testing so that what is behind it is found instead, and its descendants are still searched; the other values are kept apart in the computed style and behave as `auto`, because hit testing is the whole of this engine's interaction. No `cursor`, `resize`, `user-select` or `appearance`. Form controls are drawn as plain boxes |
| **CSS Containment 1** | Partial: `contain` takes `size`, `layout`, `paint` and `style` in any combination and both shorthands — `strict` is all four, `content` is all but size. Size containment is the one that changes geometry: the box is laid out as if it had no content, its intrinsic-width pass is skipped rather than run and discarded, and `contain-intrinsic-size` with its four axis spellings supplies the size an automatic one resolves to instead. An explicit width or height still wins. Paint containment clips the descendants to the padding box, through the same offscreen image `overflow: hidden` uses. `content-visibility: hidden` skips the contents entirely, painting the box and nothing inside it, and carries size containment with it. Layout and style containment are computed and change nothing, because nothing here escapes a box that way: there is no counter or quote scope to cut and no float leaves its formatting context. `content-visibility: auto` is `visible`, since it needs to know what is on screen |
| **CSS Transforms 1** | Partial: `transform` with `translate`, `translateX`, `translateY`, `scale`, `scaleX`, `scaleY` and `rotate`, composed left to right; `transform-origin`, which defaults to the box's centre; and the individual `translate`, `rotate` and `scale` properties, applied in that order before the `transform` list. A percentage in a translate is of the box's own size. A transform changes where a box and its descendants are painted and nothing about the layout, as the standard requires. `skew()` and `matrix()` are dropped, which is the standard's answer for a function that cannot be applied: Festina's canvas composes its matrix from translate, rotate and scale and has no call that takes a matrix, so a shear cannot be expressed at all (FINDINGS.md). A transformed box does not establish a stacking context or a containing block for its positioned descendants, and hit testing uses the untransformed box, so a click lands where the box was laid out rather than where it is drawn |
| **Compositing and Blending 1** | **Nothing.** No `mix-blend-mode`, `isolation` or `background-blend-mode` |
| **CSS Easing 1** | **Nothing** |
| **CSS Counter Styles 3** | Substantially. All five systems — `cyclic`, `fixed`, `symbolic`, `alphabetic`, `numeric` and `additive` — with `symbols`, `additive-symbols`, `prefix`, `suffix`, `pad` and `negative`, available both to `@counter-style` and to the predefined styles, which are built out of the same five and are nothing more than built-in definitions. `decimal`, `decimal-leading-zero`, the Latin and Greek alphabetics, the two romans with their 1 to 3999 range, `cjk-decimal` and the three bullets are defined; a number a system cannot write falls back to decimal, as the standard says, which is why `lower-roman` of 4000 is `4000` rather than four thousand M's. No `range`, `fallback` or `speak-as` descriptors, no `symbols()` function, and none of the predefined styles that need a table this repository would have to vendor — `hebrew`, `armenian`, `georgian` and the East Asian ones beyond `cjk-decimal` |

## 2. Reliable candidate recommendations

Grid is most of this class, Media Queries 4 substantially all of it and
Cascade 5 the whole of `@layer`; nothing else in it is implemented.

| Specification | Engine |
|---|---|
| Media Queries 4 | The syntax this level adds: the range form — `(width >= 400px)`, `(400px <= width)` with the value first and the operator turned round, and `(400px <= width <= 900px)` with both ends — in `<`, `<=`, `>`, `>=` and `=`; `or` beside `and`; `not` inside a condition; and parentheses grouping conditions rather than only enclosing features. A range on an exact ratio still compares two whole numbers. It answers its own features too, each a statement about this browser rather than a computation: `scripting` is `none`, because there is no JavaScript engine; `overflow-block` is `scroll` and `overflow-inline` is `none`, because the shell scrolls a document down and clips what runs across; `update` is `fast`; `color-gamut` is `srgb`, because every colour is a packed sRGB integer by the time it is painted; `prefers-color-scheme` is `light`; and `prefers-reduced-motion`, `prefers-contrast`, `prefers-reduced-data`, `prefers-reduced-transparency`, `forced-colors`, `inverted-colors` and `dynamic-range` answer `no-preference`, `none` or `standard`, there being no user to have asked and nothing that moves. A discrete feature takes only equality from the range form, since keywords have no order. Not answered: the features about a device's own preferences that this has no way to learn, and `environment-blending`, `horizontal-viewport-segments` and `vertical-viewport-segments` |
| CSS Scroll Snap 1 | Nothing |
| CSS Scrollbars 1 | Nothing |
| CSS Grid 1 and 2 | Substantially, in one axis-symmetric algorithm: `display: grid` and `inline-grid` establish a grid container; `grid-template-columns` and `grid-template-rows` take lengths, percentages, `auto`, `fr` and `repeat()` of a whole list; items are auto-placed in row or column order by `grid-auto-flow`, taking the first free run of cells wide enough, and an item that names one axis keeps it while the other is chosen; `grid-column-start`/`-end` and the row pair place an item by line number, counting back from the end when negative, or by `span n`, with `grid-column`, `grid-row` and `grid-area` as their shorthands; tracks past the explicit template are implicit and sized by `grid-auto-columns`/`grid-auto-rows`; `row-gap` and `column-gap` separate the tracks and come out of what the `fr` tracks share. An `auto` track is as large as the largest item that sits in it alone, which is the standard's rule and keeps the sizing to one pass. No named lines or `grid-template-areas`, no `minmax()`, `min-content`, `max-content` or `fit-content()`, no `auto-fill`/`auto-fit`, no dense packing, and no subgrid |
| CSS Cascade 5 | `@layer` orders the cascade. A layer is declared where it is first named — by a `@layer a, b;` statement or by a `@layer a { }` block — and its place in that order is its place in the cascade, above specificity and above source order: of two layered declarations the one in the later layer wins, and a declaration in no layer beats both. `!important` reverses all of it, so an important declaration in the *earliest* layer is the strongest author one and an important unlayered declaration the weakest. `@layer b` inside `@layer a` is the layer `a.b`, and declaring `a.b` declares `a` first. An anonymous `@layer { }` is a layer nothing can name again. 256 layers are kept apart; a sheet with more competes on specificity from there on, as does a sheet with more than a million rules, because the three tiers share one integer |
| CSS Color Adjustment 1 | Nothing |
| CSS Conditional 4 | Nothing. No `@container` |

## 3. Fairly stable, limited implementation experience

| Specification | Engine |
|---|---|
| CSS Display 3 | Partial: `none`, `block`, `flow-root`, `inline`, `inline-block`, `list-item`, `contents` and the table values. An element with `contents` generates no box: its children become its parent's in its place, its own height, border and background describe a box that does not exist, and it is still in the tree for inheritance, so its children inherit from it. An unknown value is dropped as the invalid declaration it is, which leaves the element the display the user-agent stylesheet gave it rather than the property's initial value — the two differ for every element the stylesheet makes a block. `inline-table` is not inline: it lays out as a block-level table. No two-value syntax |
| CSS Text 3 | Partial: `text-align`, `text-align-last`, `text-indent`, `text-transform`, `letter-spacing`, `word-spacing`, `tab-size` as a count of spaces or a length, and `word-break` and `overflow-wrap`, which break inside a word — `break-all` to fill the line it is on, `break-word` only once the word would not fit on a line of its own. `white-space` is stored as the two things it is a shorthand for, `white-space-collapse` and `text-wrap-mode`, so all five of its values are distinct and either longhand can be set on its own; `pre-line` keeps newlines while collapsing runs of spaces. `justify` renders as left, and `break-spaces` as `pre-wrap`, since neither engine breaks inside a run of preserved spaces. A tab expands to whole spaces rather than advancing to a tab stop. `hyphens` honours a soft hyphen as a break opportunity, which shows a hyphen only where the line actually breaks there; `auto` behaves as `manual`, since automatic hyphenation needs a dictionary per language. No `line-break` or `text-wrap-style` |
| CSS Text Decoration 3 | Substantially: all three lines — `underline`, `overline` and `line-through` — with `text-decoration-color`, `text-decoration-style` in all five values (`solid`, `double`, `dotted`, `dashed` and a `wavy` drawn as stepped segments, since the canvas has no curve), `text-decoration-thickness` and `text-underline-offset`. `text-shadow` casts offset and blurred copies of the text and its decorations, the blur approximated by repeated draws at a fraction of the alpha as `box-shadow`'s is. The property is not inherited; it propagates to descendant boxes for painting, and its colour, style, thickness and offset propagate with it, so a decoration crossing a differently coloured descendant keeps the colour of the box that asked for it. Where two ancestors decorate the same text differently only the nearer one's appearance survives, because one set of fields cannot hold two answers. `text-emphasis` draws a mark beside every character, over the text or under it, in all five of the standard's shapes in either their filled or open form and from a `<string>` as itself — each resolved to the character to draw, so the shapes need no drawing code. The mark does not reserve space, so in a line only as tall as its font it falls outside the line rather than growing it. `text-underline-position: under` drops the underline below the descenders; `left` and `right` behave as `auto`, because they mean something only in a vertical writing mode. No `text-decoration-skip-ink`, which needs the glyph outlines Festina does not expose |
| CSS Box Alignment 3 | What Flexible Box 1 uses — `justify-content`, `align-items`, `align-self`, `align-content` and the `gap` family on a flex container — plus `justify-items` and `justify-self` on a block container, which move a block-level box in the inline axis of its containing block once it has been sized, into space it is not already using. An auto margin wins over them, as the standard says. Nothing on a table, no `align-*` on a block, and no `safe`/`unsafe` overflow keywords |
| CSS Fragmentation 3 | Partial, in the one fragmented context that exists here: `break-before` and `break-after` take `column` to force a column break and `avoid` or `avoid-column` to forbid one, and `break-inside: avoid` makes a child indivisible, so it moves into a column whole. `page` and the page-side keywords compute but ask for a break in a paginated context, which a screen render never makes — the same answer Chromium gives them on screen. A forbidden break moves to the first allowed point after it, which is how a column comes to hold more than its balanced share. No fragment boxes: a child split between columns is refitted to the part in its first column rather than drawn as two boxes with two sets of borders, and `box-decoration-break` has nothing to say as a result |
| CSS Masking 1 | Partial: `clip-path` over the basic shapes — `inset()` with its one-to-four lengths, `circle()` and `ellipse()` with a radius per axis, a centre and the `closest-side` and `farthest-side` keywords, and `polygon()` — and over the four geometry boxes, which name a rectangle each. The canvas has no clip region and no path API, so a shape is cut the way every other clip here is: the subtree is painted into an image and blitted back, a scanline at a time, each with the span the shape covers at that row (FINDINGS.md). A pixel belongs to the shape when its centre does, which is what a rasteriser with no antialiasing has to say. `inset()`'s `round` radius is parsed and dropped, since a rounded corner needs that path API. A clip inside another clipped subtree does not clip again, which is the same limit `overflow: hidden` has here. No masks: `mask` and its longhands, `mask-type` and `clip-rule` are untouched |
| CSS Shapes 1 | Partial: `shape-outside` over the same basic shapes as `clip-path` — `inset()`, `circle()`, `ellipse()`, `polygon()` and the four geometry boxes, the default being the margin box — and `shape-margin`, which grows the shape on every side. A line box is a rectangle, so it clears the furthest the shape reaches anywhere in the band it occupies, and that answer is clamped to the float's own margin box: outside it there is no float to exclude anything. `shape-margin` on a polygon is a square outset rather than the round one the standard describes, which differs only within the margin of a vertex, and it grows a circle's radius rather than taking the true Minkowski sum, which for a circle is the same thing. No `shape-image-threshold`, which needs a shape read out of an image's alpha channel |
| CSS Writing Modes 4, Speech 1, View Transitions 1 | Nothing |

## 4. Rough interoperability

| Specification | Engine |
|---|---|
| CSS Lists and Counters 3 | All of it that applies here: `list-style-type` from any counter style, `list-style-position` inside or outside the box, `list-style-image` drawn at the image's own size with the type's marker as its fallback, and the `<ol type>` attribute the standard maps to it |
| CSS Logical Properties 1 | The whole inline and block box: `inline-size` and `block-size` with their minima and maxima, every margin, padding, border and inset alias, and the four logical corner radii. They map onto their physical twins, which is exact in the left-to-right horizontal mode this engine lays out in; `direction: rtl` reorders the text on a line but does not yet swap the inline edges those aliases resolve to |
| CSS Box Sizing 3 | `box-sizing` works, so a declared width or height can be the border box, and `max-height` is honoured rather than inert. No intrinsic keywords (`min-content`, `fit-content`) |
| CSS Positioned Layout 3 | CSS2's positioning is implemented (above), and the `inset` shorthand with its block and inline forms. Nothing else this level adds: no stacking contexts beyond painting positioned siblings in z-index order, and no `sticky` behaviour — it computes as `relative` |
| Selectors 4 | The five the measurement used to fail, which were all from here: `:is()` and `:where()`, which differ only in that `:where()` contributes no specificity; `:has()`, as a descendant test; a selector list inside `:not()`; and the attribute case-sensitivity flag. `:has()` with a leading combinator — `:has(> p)` — names a relation this engine does not distinguish and is refused rather than read as a descendant test. Nothing else from this level |
| CSS Color 5 | `color-mix()` over every interpolation space the standard names: the rectangular `srgb`, `srgb-linear`, `xyz`, `xyz-d65`, `xyz-d50`, `lab` and `oklab`, and the polar `hsl`, `hwb`, `lch` and `oklch` with all four hue-interpolation methods. Mixing is premultiplied, so a transparent colour contributes its alpha and nothing else, and percentages that do not add to a hundred are normalised with what they came to carried into the result's alpha. Each space needed the conversion the wider colour spaces did not — sRGB *into* it rather than out of it — which is what made the polar spaces possible. The **relative colour syntax** came of the same conversions: `rgb(from <color> r g b)` and its form in every other colour function, with the origin colour's channels bound to the names that function writes them with, `calc()` over them, percentages on each function's own scale, and `none`. `color(from <color> <space> ...)` takes all eight predefined spaces, which needed the XYZ-to-linear matrices for the four wide RGB ones — the inverses of what the absolute forms use, and what the identity check proves right |
| CSS Transforms 2 | The individual `translate`, `rotate` and `scale` properties, which this level adds; nothing three-dimensional |
| CSS Containment 2 | `content-visibility: hidden`, which skips an element's contents and carries size containment with it. No `content-visibility: auto`, which needs to know what is on screen |
| CSS Nesting 1 | A style rule inside a style rule, and the `&` that stands for the rule it is in: `&` anywhere in the nested selector, a nested selector with none, which gets one in front as a descendant, and a leading `>`, `+` or `~`, which gets one before the combinator. Nesting nests, and so do `@media`, `@supports` and `@layer`, in both directions: a style rule inside a nested at-rule, and declarations directly inside one, which belong to the rule the at-rule is in. A declaration written after a nested rule cascades after it, so a rule's declarations are emitted as the runs they are written in rather than gathered into one. A nested rule expands to the cross product of its own selector list with its parent's, up to 256 selectors; `&` in it weighs the most specific selector of the parent list, whichever branch a match came through, which is a correction applied to each expansion rather than a property of its text. An `&` inside `:is()` or `:not()` is refused rather than substituted, because those take a compound selector here and a parent may be a complex one. Nesting is syntax rather than a property, so the property instrument cannot grade it whatever it does; `tests/unit/test_nesting.f` does, against what Chromium computes off the same stylesheet and the same document |
| CSS Transitions 1, Animations 1, Motion Path 1, Will Change 1, Filter Effects 1, Fonts 4, Scroll Anchoring 1 | Nothing. `@keyframes` blocks are skipped, and nothing here would run them: an animation needs a clock and a repaint loop, which is an addition to the browser shell rather than a property |
| CSSOM, CSSOM View, Geometry 1, Font Loading 3, Web Animations 1, Resize Observer 1 | Out of scope permanently: these are script interfaces, and there is no JavaScript engine (todo.md, "Deliberate non-work") |

## What this changes about the plan

**The snapshot's classification and this project's priorities do not
agree, and the classification wins on two counts.** Custom properties
with `calc()`, flexbox, and CSS Images are in the official definition of
CSS, not in some forward-looking tier: an engine missing them is missing
stable CSS, not modern CSS. Conversely `:is()`, `:where()`, `:has()` and
`@layer` ordering sit in the two lowest classes, so they are further
down the list than their prominence suggests.

**Positioning is official-definition work too**, through CSS2 §9.3
rather than through Positioned Layout 3. So are floats, `overflow`
clipping and generated content. The four largest holes in the engine are
all CSS2 chapters.

**The cascade bugs are fixed.** Specificity is compared as a triple,
importance inverts the origin order, `inherit` takes the parent's value,
`@supports` evaluates its condition, `text-decoration` and `opacity` no
longer inherit, `rem` and `vh` resolve against the real root font size
and viewport, and an unparseable selector drops its whole rule. What
remains of Cascade 4 is `revert` and `all`.

**A corpus is still the missing instrument.** The HTML parser went from
20% to 93% because someone else's tests said what was wrong; `css/` in
web-platform-tests is the equivalent, and the open question is how much
of it runs without script.
