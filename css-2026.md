# CSS: what the style engine implements, against the 2026 snapshot

The target is the **[CSS Snapshot 2026](https://www.w3.org/TR/css-2026/)**
(CLAUDE.md, §2). The snapshot sorts specifications into four classes;
this file takes them in its order and states, for each, what the engine
does. The work it implies is in [todo.md](todo.md).

**The engine column is read from the code**, not from the other
documents: all of `src/css/`, plus the places `src/layout/layout.f` and
`src/paint/paint.f` consume a computed value. A property the cascade
computes but neither reads counts as absent, because a page renders the
same either way. That rule is what excludes `overflow`.

`www.w3.org` is refused by this network's egress policy — the proxy's
CONNECT is answered 403 — so the snapshot has to be supplied to a
session rather than fetched, as it was for this one.

## The headline

The official definition of CSS is 24 specifications. **The engine
implements no part of 8 of them** and part of the other 16. Nothing in
the three lower classes is implemented at all, except a fragment of
`@layer` and the `color-mix()`-less parts of Color 5, which amount to
nothing either.

Two runners in `tests/conformance/` put numbers on it, and both are
floors the suite will not let drop:

| Measure | Now |
|---|---|
| CSS properties that change what renders, of the 373 Chromium reports | **78** |
| HTML elements whose default `display` matches Chromium's, of 121 | **121** |

The property count uses the same rule as this file: a property the
cascade computes but neither layout nor paint reads is not implemented,
because the page renders the same either way. `overflow` is what
still falls to it.

## 1. The official definition

Everything here is stable, and the snapshot's own framing is that this
is CSS "in its most complete form". The gaps in this table are the ones
that matter first.

| Specification | Engine |
|---|---|
| **CSS Level 2** | The bulk of what works: normal flow with margin collapsing, inline formatting and line boxes, automatic table layout (§17) with `caption-side`, list markers, and **positioning** (§9.3) — `relative` offsets a box and its descendants without disturbing the flow, `absolute` and `fixed` leave the flow and resolve against the nearest positioned ancestor or the viewport, all four inset properties work, and `z-index` orders positioned siblings. **Floats** (§9.5) work too: a float is placed at the edge of its containing block after any float already there, the line boxes beside it are shortened so text wraps around it, a block box's own position and width ignore it, and `clear` moves a box below the floats on a side. Missing from CSS2 itself are **`overflow` and clipping** (§11), **generated content and counters** (§12) and **paged media** (§13). A margin that collapses all the way through to the root is dropped rather than moving the document down |
| **CSS Syntax 3** | Partial, and not by this algorithm. There is no tokenizer in the standard's sense: parsing is index scanning. Comment stripping runs first and is not string-aware, so `/*` inside a string or `url()` opens a comment. Escapes are accepted in identifiers and never decoded, so `.a\.b` can never match. No `<!--`/`-->` |
| **CSS Style Attributes** | Yes. The `style` attribute is parsed per element, though it is treated as an origin above author rules rather than as a specificity |
| **Media Queries 3** | Partial: a comma list, leading `not` and `only`, `and` terms, the four media types, and `min-width`, `max-width`, `min-height`, `max-height`, `width`. `(color)` and `(hover)` are hard-coded true and every other feature is false. Queries are evaluated once at parse time, so a resize does not re-evaluate them, and height features compare against a viewport height fixed at 600 |
| **CSS Conditional 3** | Both. `@supports` evaluates its condition: a declaration is supported when the property is one the cascade computes and the value uses no function the engine cannot resolve. `not`, `and`, `or` and nesting are handled; `selector()` reports unsupported |
| **Selectors 3** | Partial. Present: type, `*`, `#id`, `.class`, all six attribute operators, all four combinators, `:first-child`, `:last-child`, `:only-child`, `:first-of-type`, `:last-of-type`, `:root`, `:link`, `:not()` with one compound. A rule whose selector list contains anything unparseable is dropped whole, as §4 requires. Missing: `An+B` in `:nth-child()` (only `odd`, `even` and an integer), the whole `:nth-last-child` / `:nth-of-type` / `:nth-last-of-type` / `:only-of-type` family, `:empty`, `:target`, `:enabled`, `:disabled`, `:checked`, `:lang()`, and **every pseudo-element** — no `::before`, `::after`, `::first-line`, `::first-letter` |
| **CSS Namespaces 3** | Nothing. `@namespace` is skipped as a statement at-rule and there are no namespace-prefixed selectors |
| **CSS Cascade 4** | Substantially. Specificity is the triple (ids, classes and attributes and pseudo-classes, types), packed base 1024 so that an integer comparison is the lexicographic one. Importance inverts the origin order, so an important user-agent declaration outranks an important author one. `inherit` takes the parent's computed value, `initial` the initial value, and `unset` whichever of the two the property calls for. Missing: `revert`, which needs the origins kept apart after the cascade and behaves as `unset`, and `all` |
| **CSS Values and Units 3** | Partial. Units: unitless, `px`, `%`, `em`, `rem`, `pt`, `pc`, `in`, `cm`, `mm`, `ex`, `ch`, `vw`, `vh`, `vmin`, `vmax`. Missing `q`, and all angle, time, frequency and resolution units. `calc()` is implemented: a sum of products over lengths and plain numbers, with nested parentheses and nested `calc()`, and a result that carries a pixel part and a percentage part separately so `calc(100% - 2em)` waits for the containing block. The standard's invalid cases are rejected, among them a `-` without spaces around it and a length added to a number. `attr()` is missing. `rem` multiplies the root element's computed font size and `vh` the real viewport height |
| **CSS Custom Properties 1** | Yes. Custom properties are kept, inherit, and `var(--name, fallback)` substitutes them wherever a value is read, including inside another custom property. An unresolvable `var()` with no fallback makes the declaration invalid rather than empty, as the standard requires. A vendor prefix is still dropped |
| **CSS Box Model 3** | Yes, in substance: all four margins and paddings, and margin collapsing, which CSS2 §8.3.1 still owns |
| **CSS Color 4** | Partial: `transparent`, `currentcolor`, all four hex forms, `rgb()`, `rgba()`, `hsl()`, `hsla()` with either separator and alpha, all 148 named colors, and `opacity`. Missing every wider color space — `hwb()`, `lab()`, `lch()`, `oklab()`, `oklch()`, `color()` — and the system colors. `opacity` is not inherited: its computed value is the element's own, and a separate accumulated value carries group opacity to the painter, which approximates it rather than compositing a layer |
| **CSS Backgrounds and Borders 3** | Partial: `background-color`, per-side border width, style and color, the `border` shorthands, and `border-radius`. Every border style paints solid — `dashed`, `dotted` and `double` are accepted only to make the width non-zero. `border-radius` takes the first token in px, with no percentage and no elliptical form. No background image or layers, position, repeat, size, attachment, clip or origin; no `border-image`; no `box-shadow` |
| **CSS Images 3** | Partial: `linear-gradient()` and `repeating-linear-gradient()` as a background image, with `to <side>` and `to <corner>` keywords, an angle in `deg`, `turn`, `rad` or `grad`, any number of colour stops, and stop positions in percentages, lengths, or omitted and spaced evenly. Painted as flat bands rather than by the canvas's own gradient, which cannot be called with colours that are not literals (FINDINGS.md, "a gradient cannot be built at run time"). Missing: `radial-gradient()` and `conic-gradient()`, `image()`, `image-set()`, `cross-fade()`, `object-fit` and `object-position`, and gradient interpolation hints |
| **CSS Fonts 3** | Partial: `font-family`, `font-size` with the absolute and relative keywords, `font-style`, the `font` shorthand, and `font-weight` **as a boolean** — 300 and 400 render identically. No `@font-face`, `font-variant`, `font-feature-settings`, `font-stretch` or `unicode-range` |
| **CSS Writing Modes 3** | **Nothing.** No `direction`, `unicode-bidi`, `writing-mode` or `text-orientation`. Left-to-right horizontal is assumed throughout, including by the logical-property aliases the cascade does implement |
| **CSS Multi-column 1** | **Nothing** |
| **CSS Flexible Box 1** | Partial, and enough for the single-line case a modern page is built on: `display: flex` and `display: inline-flex` both establish a flex container, and an inline-flex one is inline-level and shrinks to fit, `flex-direction` takes all four values, `order` reorders the items, `flex-grow`, `flex-shrink` and `flex-basis` distribute the free space (with the `flex` shorthand, including its `initial`, `auto` and `none` keywords, and the rule that a bare `flex: 1` zeroes the basis so the whole line is shared rather than the slack), `justify-content` takes all six values, and `align-items` and `align-self` take `stretch`, `flex-start`, `flex-end` and `center`, with the Box Alignment 3 synonyms `start`, `end`, `left`, `right` and `normal`. `gap`, `row-gap` and `column-gap` separate the items. Missing: `flex-wrap` — every container is single-line, so `align-content` has nothing to align — `baseline` alignment, and auto margins inside a flex container |
| **CSS Basic User Interface 3** | `outline` only, with its longhands: drawn just outside the border box, taking no space, every style painting solid as every border style does. No `cursor`, `resize` or `text-overflow`. Form controls are drawn as plain boxes |
| **CSS Containment 1** | **Nothing** |
| **CSS Transforms 1** | **Nothing** |
| **Compositing and Blending 1** | **Nothing.** No `mix-blend-mode`, `isolation` or `background-blend-mode` |
| **CSS Easing 1** | **Nothing** |
| **CSS Counter Styles 3** | **Nothing.** No `@counter-style`, and not even the predefined styles: `lower-alpha`, `upper-alpha`, `lower-roman` and `upper-roman` all render as arabic numerals |

## 2. Reliable candidate recommendations

Nothing in this class is implemented.

| Specification | Engine |
|---|---|
| Media Queries 4 | Nothing beyond the Level 3 subset above. No range syntax, no `or`, no negation inside a condition |
| CSS Scroll Snap 1 | Nothing |
| CSS Scrollbars 1 | Nothing |
| CSS Grid 1 and 2 | Nothing. `grid` and `inline-grid` are accepted and laid out as blocks |
| CSS Cascade 5 | `@layer` blocks have their contents parsed, and the ordering — the entire point — is discarded, so a layered sheet competes purely on specificity |
| CSS Color Adjustment 1 | Nothing |
| CSS Conditional 4 | Nothing. No `@container` |

## 3. Fairly stable, limited implementation experience

| Specification | Engine |
|---|---|
| CSS Display 3 | Partial: `none`, `block`, `flow-root`, `inline`, `inline-block`, `list-item` and the table values. `contents` wrongly generates a box, `inline-table` is not inline, and an unknown value falls back to `inline` rather than `block`. No two-value syntax |
| CSS Text 3 | Partial: `text-align`, `text-indent`, `text-transform`, `white-space`, `letter-spacing`, `word-spacing`. `justify` renders as left; `pre-line` behaves as `pre-wrap` and wrongly keeps runs of spaces. No `word-break`, `overflow-wrap`, `hyphens`, `tab-size` |
| CSS Text Decoration 3 | Partial: `underline` and `line-through` only. No `overline`, no decoration colour, style or thickness. The property is not inherited; it propagates to descendant boxes for painting, as the standard requires |
| CSS Box Alignment 3 | Only what Flexible Box 1 uses: `justify-content`, `align-items`, `align-self` and the `gap` family, on a flex container. Nothing on a block or a table, no `justify-items`, `justify-self` or `align-content`, and no `safe`/`unsafe` overflow keywords |
| CSS Writing Modes 4, Fragmentation 3, Shapes 1, Masking 1, Speech 1, View Transitions 1 | Nothing |

## 4. Rough interoperability

| Specification | Engine |
|---|---|
| CSS Lists and Counters 3 | Partial: `list-style-type` and markers, with the alphabetic and roman styles rendering as numerals. No `list-style-position`, no `list-style-image`, no counters |
| CSS Logical Properties 1 | Partial: `inline-size`, `block-size`, and the inline and block margin and padding aliases — all assuming left-to-right horizontal. `padding-block-start` and `padding-block-end` are not aliased |
| CSS Box Sizing 3 | `box-sizing` works, so a declared width or height can be the border box, and `max-height` is honoured rather than inert. No intrinsic keywords (`min-content`, `fit-content`) |
| CSS Positioned Layout 3 | CSS2's positioning is implemented (above). Nothing this level adds: no stacking contexts beyond painting positioned siblings in z-index order, no `inset` shorthand, no `sticky` behaviour — it computes as `relative` |
| Selectors 4 | Nothing beyond Level 3. No `:is()`, `:where()`, `:has()`, no selector list in `:not()`, and the attribute case-sensitivity flag is parsed and thrown away |
| CSS Color 5 | Nothing. No `color-mix()`, no relative colour syntax |
| CSS Transitions 1, Animations 1, Transforms 2, Motion Path 1, Will Change 1, Filter Effects 1, Fonts 4, Nesting 1, Containment 2, Scroll Anchoring 1 | Nothing. `@keyframes` blocks are skipped |
| CSSOM, CSSOM View, Geometry 1, Font Loading 3, Web Animations 1, Resize Observer 1 | Out of scope permanently: these are script interfaces, and there is no JavaScript engine (todo.md, "Deliberate non-work") |

## What this changes about the plan

**The snapshot's classification and this project's priorities do not
agree, and the classification wins on two counts.** Custom properties
with `calc()`, flexbox, and CSS Images are in the official definition of
CSS, not in some forward-looking tier: an engine missing them is missing
stable CSS, not modern CSS. Conversely `:is()`, `:where()`, `:has()` and
`@layer` ordering sit in the two lowest classes, so they are further
down the list than their prominence suggests.

**Positioning is official-definition work too**, through CSS2 §9.3
rather than through Positioned Layout 3. So are floats, `overflow`
clipping and generated content. The four largest holes in the engine are
all CSS2 chapters.

**The cascade bugs are fixed.** Specificity is compared as a triple,
importance inverts the origin order, `inherit` takes the parent's value,
`@supports` evaluates its condition, `text-decoration` and `opacity` no
longer inherit, `rem` and `vh` resolve against the real root font size
and viewport, and an unparseable selector drops its whole rule. What
remains of Cascade 4 is `revert` and `all`.

**A corpus is still the missing instrument.** The HTML parser went from
20% to 93% because someone else's tests said what was wrong; `css/` in
web-platform-tests is the equivalent, and the open question is how much
of it runs without script.
