# CSS: what the style engine implements, module by module

The target is the **[CSS Snapshot 2026](https://www.w3.org/TR/css-2026/)**
(CLAUDE.md, §2). This file states where the engine stands against it, so
the work in todo.md is ordered by measurement rather than by guess.

## How this was measured

**The engine column is read from the code**, not from the documents: the
whole of `src/css/` plus the places `src/layout/layout.f` and
`src/paint/paint.f` consume a computed value. A property that the cascade
computes but no one reads is recorded as absent, because a page renders
the same either way.

**The module column is the module directories of the W3C's own test
suite** (`css/` in web-platform-tests, 91 of them, two of which —
`CSS1` and `CSS2` — are the legacy suites rather than modules). The
snapshot's own
list is the better axis and is not used here, because `www.w3.org` is
refused by this network's egress policy — the CONNECT is answered 403,
the same way `html.spec.whatwg.org` is (todo.md records the one place
that cost us on the HTML side). So this file does not reproduce the
snapshot's classification of a module as stable, still in testing, or
abandoned. Whoever can reach the snapshot should add that column; the
engine column does not change when they do.

Most of what does work is CSS2: normal flow with margin collapsing,
inline formatting, automatic table layout and list markers. The modules
below say how far past that the engine reaches.

## Implemented, with gaps

| Module | What the engine has | What is missing |
|---|---|---|
| `css-syntax` | Comment stripping, quote-aware declaration splitting, `!important`, at-rule prelude/block scanning, per-rule error recovery | No tokenizer in the standard's sense. Comment stripping is not string-aware, so `/*` inside a string or `url()` opens a comment. Escapes are accepted in identifiers and never decoded, so `.a\.b` can never match. No `<!--`/`-->`, no nested style rules. An unparseable selector drops only itself; the standard drops the whole rule |
| `selectors` | Type, `*`, `#id`, `.class`, all six attribute operators plus `[attr]`, all four combinators, `:first-child`, `:last-child`, `:only-child`, `:first-of-type`, `:last-of-type`, `:root`, `:link`, `:any-link`, `:nth-child()`, `:not()` | `:nth-child()` takes only `odd`, `even` or an integer — no `An+B`. `:not()` takes one compound, not a list. No `:is()`, `:where()`, `:has()`, `:nth-of-type()`, `:empty`, `:checked`, `:disabled`, `:hover`, `:focus`, `:target`, `:lang()`. No pseudo-elements at all. The attribute case-sensitivity flag is parsed and ignored. No namespaces |
| `css-cascade` | Specificity, source order, three origins, `!important`, inline style, HTML presentational attributes | Specificity is collapsed into one integer rather than compared as a triple, weighted 10000 / 100 / 1, so a hundred classes tie an id and a hundred and one beat it. `!important` does not invert the origin order, so an important author rule beats an important UA rule. `@layer` contents are flattened with no ordering. `inherit` returns the initial value for most properties rather than the parent's. `initial` and `unset` are honoured only where a length is expected. No `revert`, no `all` |
| `css-values` | Unitless, `px`, `%`, `em`, `rem`, `pt`, `pc`, `in`, `cm`, `mm`, `ex`, `ch`, `vw`, `vh`, `vmin`, `vmax` | No `calc()`, `min()`, `max()`, `clamp()`, `attr()`, `env()`. No `q`, `cap`, `ic`, `lh`, `rlh`, logical or dynamic viewport units, container units. `rem` multiplies a hard-coded 16 rather than the real root font size, and the viewport height is fixed at 600, so every `vh` is wrong on any other window |
| `css-color` | `transparent`, `currentcolor`, all four hex forms, `rgb()`, `rgba()`, `hsl()`, `hsla()` with either separator and alpha, and all 148 named colors | No `hwb()`, `lab()`, `lch()`, `oklab()`, `oklch()`, `color()`, `color-mix()`, `light-dark()`, relative color syntax, or system colors |
| `css-display` | `none`, `block`, `flow-root`, `inline`, `inline-block`, `list-item`, `table` and the table-internal values | `flex`, `inline-flex`, `grid` and `inline-grid` are accepted and laid out as blocks. `contents` wrongly generates a box. `inline-table` is not inline. Unknown values fall back to `inline`, not `block`. No two-value syntax |
| `css-box`, `css-sizing` | All four margins and paddings, `width`, `height`, `min-width`, `max-width`, `min-height` | `max-height` is inert. A percentage `height` or `min-height` is ignored. No `box-sizing`, so every box is content-box. No `aspect-ratio`, no intrinsic keywords (`min-content`, `fit-content`) |
| `css-borders`, `css-backgrounds` | Per-side width, style and color, the `border` shorthands, `border-radius`, and `background-color` | Every border style paints solid: `dashed`, `dotted` and `double` are accepted only to make the width non-zero. `border-radius` takes the first token in px, with no percentage and no elliptical form. No background image, position, repeat, size, attachment, clip or origin. No `box-shadow`, no `outline` |
| `css-text` | `text-align`, `text-indent`, `text-transform`, `white-space`, `letter-spacing` | `justify` renders as left. `pre-line` behaves as `pre-wrap` and wrongly keeps runs of spaces. No `word-spacing`, `word-break`, `overflow-wrap`, `hyphens`, `text-overflow`, `tab-size` |
| `css-text-decor` | `underline` and `line-through` | No `overline`. No decoration color, style or thickness. The property is inherited here, which the standard does not do: it propagates to descendants instead |
| `css-fonts` | `font-family`, `font-size` including the absolute and relative keywords, `font-weight` as a bold flag, `font-style`, and the `font` shorthand | Weight is a boolean, so 300 and 400 render identically. No `@font-face`, `font-variant`, `font-stretch`, `font-feature-settings`, or font loading |
| `css-inline` | Baseline alignment, line boxes, `line-height`, `vertical-align` | `vertical-align` collapses `top`/`text-top`/`super` to one behaviour and the bottom set to another; length and percentage offsets are ignored |
| `css-lists` | `list-style-type` and markers | `lower-alpha`, `upper-alpha`, `lower-roman` and `upper-roman` all render as arabic numerals. No `list-style-position`, no `list-style-image` |
| `css-tables` | Automatic table layout, fixed and percentage columns, `colspan`, row heights, `border-spacing`, and `border-collapse` as far as spacing and which edges paint | No real border-conflict resolution. No `table-layout`, `caption-side` (captions always go above), or `empty-cells`. `<col>` and `<colgroup>` are skipped, so a column width set there is lost |
| `css-logical` | `inline-size`, `block-size`, and the inline and block margin and padding aliases | Every alias assumes left-to-right horizontal writing. `padding-block-start` and `padding-block-end` are not aliased at all |
| `mediaqueries` | A comma-separated list, leading `not` and `only`, `and` terms, the `all`/`screen`/`print`/`speech` types, and `min-width`, `max-width`, `min-height`, `max-height`, `width` | No `or`, no negation inside a condition, no nesting, no range syntax. `(color)` and `(hover)` are hard-coded true and every other feature is false, including `prefers-color-scheme` and `orientation`. Queries are evaluated once at parse time, so resizing the window does not re-evaluate them. Height features compare against the fixed 600 |
| `css-conditional` | `@media` | `@supports` never evaluates its condition and always applies its contents, so a page's fallback and its enhancement both land. No `@container` |
| `css-style-attr` | The `style` attribute, parsed per element | It is treated as its own origin above author rules rather than as a specificity |

## Not implemented

| Module | Note |
|---|---|
| `css-position` | Nothing: `position`, the inset properties and `z-index` are never parsed. Every box is static |
| `css-flexbox`, `css-grid`, `css-align`, `css-gaps` | Nothing. A flex or grid container lays out as a block, which is why a modern page renders as one column |
| `css-variables`, `css-mixins`, `css-properties-values-api` | Custom properties are dropped by name at parse time, so `var()` can never resolve |
| `css-images` | No CSS image of any kind: no gradients, no `image-set()`, no `object-fit`. Images come only from an `<img>` element |
| `css-overflow` | `overflow` is computed and never read. Nothing clips or scrolls |
| `css-transforms`, `css-transitions`, `css-animations`, `css-easing`, `motion`, `css-motion-path` | Nothing, and `@keyframes` blocks are skipped |
| `css-masking`, `filter-effects`, `compositing` | Nothing. `opacity` exists, but it is inherited and multiplied down the tree, which approximates group opacity rather than implementing it |
| `css-content`, `css-counter-styles`, `css-pseudo` | No generated content, no counters, no `::before`, `::after`, `::marker` or `::selection` |
| `css-writing-modes` | Nothing. Horizontal left-to-right is assumed throughout, including in the logical aliases above |
| `css-multicol`, `css-break`, `css-page`, `printing` | Nothing. `@page` blocks are skipped |
| `css-ui` | No `cursor`, `appearance`, `outline`, `resize`, `caret-color`. Form controls are drawn as plain boxes |
| `css-shapes`, `css-exclusions` | Nothing, and floats themselves are laid out as static, so there is nothing to shape around |
| `css-scroll-snap`, `css-scroll-anchoring`, `css-overscroll-behavior`, `css-scrollbars` | Nothing. Scrolling is a viewport offset in the shell, not a CSS-visible feature |
| `css-contain`, `css-will-change`, `css-color-adjust`, `css-forced-color-adjust`, `css-color-hdr`, `css-size-adjust`, `css-zoom`, `css-rhythm`, `css-round-display`, `css-device-adapt`, `css-viewport`, `css-gcpm`, `css-speech`, `css-navigation`, `css-link-params`, `css-image-animation`, `css-env`, `css-forms`, `css-nesting`, `css-namespaces`, `css-ruby` | Nothing. `@namespace` is skipped as a statement at-rule and `ruby` display values fall through to inline |

## Out of scope, permanently

These are script interfaces, and there is no JavaScript engine and will
not be one (todo.md, "Deliberate non-work"): `cssom`, `cssom-view`,
`css-typed-om`, `css-paint-api`, `css-layout-api`, `css-parser-api`,
`css-properties-values-api`, `css-font-loading`, `css-highlight-api`,
`css-view-transitions`, `css-anchor-position`, `geometry`, `fetching`,
`fill-stroke`, `css-shadow` (shadow DOM), `css-animations` and
`css-transitions` in their scripted parts.

## What this changes about the plan

The delta says the next work is not the feature list todo.md carried
before it. Three things stand out.

**The conformance bugs are cheaper than the features and matter more.**
Specificity collapsed into one integer, `!important` not inverting origin
order, `inherit` returning the initial value, `text-decoration` and
`opacity` inheriting when they should not, `@supports` applying every
block it sees, `rem` against a hard-coded 16 and `vh` against a fixed
600: each is a small correction in `src/css/cascade.f` or
`src/css/parser.f`, and each makes ordinary pages wrong today.

**Three absent modules explain most of what a modern page gets wrong**,
in this order: positioning, flexbox, and custom properties with `calc()`.
Grid follows. Floats are the fourth, and are a layout gap rather than a
style one.

**A corpus is the missing instrument.** The HTML side moved from 20% to
93% because someone else's tests said what was wrong. `css/` in
web-platform-tests holds the equivalent, and the open question is how
much of it runs without script.
