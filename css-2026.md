# CSS: what the style engine implements, against the 2026 snapshot

The target is the **[CSS Snapshot 2026](https://www.w3.org/TR/css-2026/)**
(CLAUDE.md, §2). The snapshot sorts specifications into four classes;
this file takes them in its order and states, for each, what the engine
does. The work it implies is in [todo.md](todo.md).

**The engine column is read from the code**, not from the other
documents: all of `src/css/`, plus the places `src/layout/layout.f` and
`src/paint/paint.f` consume a computed value. A property the cascade
computes but neither reads counts as absent, because a page renders the
same either way. Nothing is excluded by it now: `overflow` was, until
the painter began clipping by it.

`www.w3.org` is refused by this network's egress policy — the proxy's
CONNECT is answered 403 — so the snapshot has to be supplied to a
session rather than fetched, as it was for this one.

## The headline

The official definition of CSS is 24 specifications. **The engine
implements no part of 8 of them** and part of the other 16. Nothing in
the three lower classes is implemented at all, except a fragment of
`@layer` and the `color-mix()`-less parts of Color 5, which amount to
nothing either.

Three runners in `tests/conformance/` put numbers on it, and each is a
floor the suite will not let drop:

| Measure | Now |
|---|---|
| CSS properties that change what renders, of the 369 the instrument can grade | **135** |
| HTML elements whose default `display` matches Chromium's, of 122 | **122** |
| CSS selectors matching the same elements as Chromium, of 61 | **56** |

The property count uses the same rule as this file: a property the
cascade computes but neither layout nor paint reads is not implemented,
because the page renders the same either way. `overflow` is what
still falls to it.

## 1. The official definition

Everything here is stable, and the snapshot's own framing is that this
is CSS "in its most complete form". The gaps in this table are the ones
that matter first.

| Specification | Engine |
|---|---|
| **CSS Level 2** | The bulk of what works: normal flow with margin collapsing, inline formatting and line boxes, table layout (§17) in both algorithms — automatic, and the fixed one that takes its column widths from the first row and never measures a cell's content — with `caption-side` and `empty-cells`, list markers inside or outside the box, and **positioning** (§9.3) — `relative` offsets a box and its descendants without disturbing the flow, `absolute` and `fixed` leave the flow and resolve against the nearest positioned ancestor or the viewport, all four inset properties work, and `z-index` orders positioned siblings. **Floats** (§9.5) work too: a float is placed at the edge of its containing block after any float already there, the line boxes beside it are shortened so text wraps around it, a block box's own position and width ignore it, and `clear` moves a box below the floats on a side. **Generated content** (§12) works: `::before` and `::after` generate boxes from `content`, which takes strings, `attr()`, `counter()`, `counters()` and the four quote keywords, and `counter-reset` and `counter-increment` maintain counters with the standard's scoping — an instance is in force for the element that reset it, its descendants and its following siblings. `quotes` gives the strings for `open-quote` and `close-quote`, at a depth that runs over the whole document in document order rather than following element nesting, repeating the last pair past the end of the list; `<q>` gets a pair from the user-agent stylesheet. `url()` in `content` does not exist, and a counter is always rendered in decimal. **`overflow: hidden`** clips a box's descendants to its padding box, painted through an offscreen image because the canvas has no clip region — and inside such a subtree a `border-radius` is drawn square, because an image has no path API (FINDINGS.md). `::first-letter` (§5.12.2) styles the first letter of a block's first line, taking preceding punctuation with it and skipping leading whitespace. Missing from CSS2 itself are `overflow: scroll` and `auto`, which need a scrollable area rather than only a clip, `::first-line`, `url()` in `content`, and **paged media** (§13). A margin that collapses all the way through to the root is dropped rather than moving the document down |
| **CSS Syntax 3** | Partial, and not by this algorithm. There is no tokenizer in the standard's sense: parsing is index scanning. Comment stripping runs first and is not string-aware, so `/*` inside a string or `url()` opens a comment. Escapes are accepted in identifiers and never decoded, so `.a\.b` can never match. No `<!--`/`-->` |
| **CSS Style Attributes** | Yes. The `style` attribute is parsed per element, though it is treated as an origin above author rules rather than as a specificity |
| **Media Queries 3** | Partial: a comma list, leading `not` and `only`, `and` terms, the four media types, and `min-width`, `max-width`, `min-height`, `max-height`, `width`. `(color)` and `(hover)` are hard-coded true and every other feature is false. Queries are evaluated once at parse time, so a resize does not re-evaluate them, and height features compare against a viewport height fixed at 600 |
| **CSS Conditional 3** | Both. `@supports` evaluates its condition: a declaration is supported when the property is one the cascade computes and the value uses no function the engine cannot resolve. `not`, `and`, `or` and nesting are handled; `selector()` reports unsupported. The list of properties it answers from is checked against the property instrument on every run: a property that changes what renders and is not on the list, or is on the list and changes nothing, fails the suite, because a hand-written list beside a measurement drifts from it in both directions and silently |
| **Selectors 3** | Every selector this can measure, it gets right: all 56 Selectors 3 entries in `tests/conformance/css-selectors.txt` match exactly the elements Chromium matches. Type, `*`, `#id`, `.class`, all six attribute operators, all four combinators, the full `An+B` grammar in `:nth-child()`, `:nth-last-child()`, `:nth-of-type()` and `:nth-last-of-type()`, the `first`/`last`/`only` child and of-type pseudo-classes, `:root`, `:empty`, `:link`, `:enabled`, `:disabled`, `:checked`, `:lang()`, and `:not()` with one compound. A rule whose selector list contains anything unparseable is dropped whole, as §4 requires. `:target` parses and matches nothing, which is right for a document never navigated to a fragment. **`::before` and `::after` generate boxes**, in both the one- and two-colon spellings; `::first-line` and `::first-letter` do not, and make their rule unusable rather than silently matching the element |
| **CSS Namespaces 3** | Nothing. `@namespace` is skipped as a statement at-rule and there are no namespace-prefixed selectors |
| **CSS Cascade 4** | Substantially. Specificity is the triple (ids, classes and attributes and pseudo-classes, types), packed base 1024 so that an integer comparison is the lexicographic one. Importance inverts the origin order, so an important user-agent declaration outranks an important author one. `inherit` takes the parent's computed value, `initial` the initial value, and `unset` whichever of the two the property calls for. Missing: `revert`, which needs the origins kept apart after the cascade and behaves as `unset`, and `all` |
| **CSS Values and Units 3** | Partial. Units: unitless, `px`, `%`, `em`, `rem`, `pt`, `pc`, `in`, `cm`, `mm`, `ex`, `ch`, `vw`, `vh`, `vmin`, `vmax`. Missing `q`, and all angle, time, frequency and resolution units. `calc()` is implemented: a sum of products over lengths and plain numbers, with nested parentheses and nested `calc()`, and a result that carries a pixel part and a percentage part separately so `calc(100% - 2em)` waits for the containing block. The standard's invalid cases are rejected, among them a `-` without spaces around it and a length added to a number. `attr()` is missing. `rem` multiplies the root element's computed font size and `vh` the real viewport height |
| **CSS Custom Properties 1** | Yes. Custom properties are kept, inherit, and `var(--name, fallback)` substitutes them wherever a value is read, including inside another custom property. An unresolvable `var()` with no fallback makes the declaration invalid rather than empty, as the standard requires. A vendor prefix is still dropped |
| **CSS Box Model 3** | Yes, in substance: all four margins and paddings, and margin collapsing, which CSS2 §8.3.1 still owns |
| **CSS Color 4** | Partial: `transparent`, `currentcolor`, all four hex forms, `rgb()`, `rgba()`, `hsl()`, `hsla()` with either separator and alpha, all 148 named colors, and `opacity`. Missing every wider color space — `hwb()`, `lab()`, `lch()`, `oklab()`, `oklch()`, `color()` — and the system colors. `opacity` is not inherited: its computed value is the element's own, and a separate accumulated value carries group opacity to the painter, which approximates it rather than compositing a layer |
| **CSS Backgrounds and Borders 3** | Partial: `background-color`, a `background-image` from `url()` or a gradient, `background-repeat` in all five forms, `background-position` with keywords, lengths and percentages on both axes, `background-size` with `cover`, `contain`, lengths, percentages and `auto`, and `background-origin` and `background-clip` over all three box edges, per-side border width, style and color, the `border` shorthands, and `border-radius`. A background image is fetched after the cascade, since the URL only exists once styles are computed, and a tile that runs off the box is cut off there. every border style paints as itself, per side: `solid`, `dashed`, `dotted`, `double` — whose two lines and gap are each as near a third of the width as it allows — and `groove`, `ridge`, `inset` and `outset`, which shade an edge against its opposite, the two shades being the border colour and half its brightness, since the standard fixes only that they are based on it. `border-radius` sets each corner separately — the shorthand's one to four values, the four `border-*-radius` longhands and the four logical corner names — in px, with no percentage and no elliptical form, the `/` form's vertical radii being read as the horizontal ones. `box-shadow` casts outer and `inset` shadows with offset, blur, spread and a list of shadows, the blur approximated by nested rectangles whose alpha accumulates, since the canvas has no blur. No layers (one image per box) and no `background-attachment`; a clipped background keeps the border box's `border-radius` rather than deriving the smaller inner curve; no `border-image` |
| **CSS Images 3** | Partial: `linear-gradient()`, `radial-gradient()` and both repeating forms as a background image. A linear gradient takes `to <side>` and `to <corner>` keywords and an angle in `deg`, `turn`, `rad` or `grad`; a radial one takes `circle` and `ellipse`, all four extent keywords, explicit radii and `at <position>`, and a degenerate ending shape renders as the last stop. Both take any number of colour stops, positioned in percentages, lengths, or omitted and spaced evenly, and both are painted as flat bands rather than by the canvas's own gradient, which cannot be called with colours that are not literals (FINDINGS.md, "a gradient cannot be built at run time"). `object-fit` in all five values and `object-position` with keywords and lengths on both axes, sized by the specification's own algorithm and clipped to the content box. Missing: `conic-gradient()`, `image()`, `image-set()`, `cross-fade()`, gradient interpolation hints, and the degenerate ellipse with zero height but non-zero width, which renders as the last stop here rather than as the mirrored linear gradient the standard names |
| **CSS Fonts 3** | Partial: `font-family`, `font-size` with the absolute and relative keywords, `font-style`, the `font` shorthand, and `font-weight` **as a boolean**. The cascade computes the weight correctly — 600 and above are bold, as CSS says — and has nowhere to put it: Festina's font weight is a two-valued Cairo enum, so 400 and 500 render identically and so do 600 and 900 (FINDINGS.md, "a font has two weights, and no way to load one"). `@font-face` is closed by the same binding, which selects a family from the system and cannot load a file. No `font-variant`, `font-feature-settings`, `font-stretch` or `unicode-range` |
| **CSS Writing Modes 3** | **Nothing.** No `direction`, `unicode-bidi`, `writing-mode` or `text-orientation`. Left-to-right horizontal is assumed throughout, which is what lets the logical box be a renaming: the twenty-four `*-inline-*` and `*-block-*` properties, and the `inset`, `border-block` and `border-inline` shorthands, are mapped onto their physical twins and would all be wrong in any other writing mode |
| **CSS Multi-column 1** | **Nothing** |
| **CSS Flexible Box 1** | Most of it. `display: flex` and `display: inline-flex` both establish a flex container, and an inline-flex one is inline-level and shrinks to fit; `flex-direction` takes all four values and `flex-wrap` all three, with the `flex-flow` shorthand; `order` reorders the items; `flex-grow`, `flex-shrink` and `flex-basis` distribute the free space of their own line (with the `flex` shorthand, including its `initial`, `auto` and `none` keywords, and the rule that a bare `flex: 1` zeroes the basis so the whole line is shared rather than the slack); `justify-content` takes all six values; `align-items` and `align-self` take `stretch`, `flex-start`, `flex-end`, `center` and `baseline`, with the Box Alignment 3 synonyms `start`, `end`, `left`, `right` and `normal`; `align-content` distributes the lines across the cross axis and stretches them when it is not asked otherwise; an auto margin absorbs a line's free space before `justify-content` is consulted. `gap`, `row-gap` and `column-gap` separate items on a line and the lines from each other. Missing: `flex-basis: content`, the min-content floor that stops an item shrinking below its own content, and nested flex containers as flex items |
| **CSS Basic User Interface 3** | `outline` only, with its longhands: drawn just outside the border box, taking no space, and painted through the same code as a border side, so every style paints as itself — `none` draws nothing however wide it is asked to be, and a style with no width takes `medium`, and `outline-offset` moves it away from the border box and leaves the gap empty. No `cursor`, `resize` or `text-overflow`. Form controls are drawn as plain boxes |
| **CSS Containment 1** | **Nothing** |
| **CSS Transforms 1** | **Nothing** |
| **Compositing and Blending 1** | **Nothing.** No `mix-blend-mode`, `isolation` or `background-blend-mode` |
| **CSS Easing 1** | **Nothing** |
| **CSS Counter Styles 3** | Partial: the predefined `lower-alpha`, `upper-alpha`, `lower-latin`, `upper-latin`, `lower-roman` and `upper-roman` number as themselves — bijective base 26 for the letters, the subtractive form for the numerals, each falling back to decimal for a value it cannot write. No `@counter-style`, and none of the other predefined styles |

## 2. Reliable candidate recommendations

Nothing in this class is implemented.

| Specification | Engine |
|---|---|
| Media Queries 4 | Nothing beyond the Level 3 subset above. No range syntax, no `or`, no negation inside a condition |
| CSS Scroll Snap 1 | Nothing |
| CSS Scrollbars 1 | Nothing |
| CSS Grid 1 and 2 | Nothing. `grid` and `inline-grid` are accepted and laid out as blocks |
| CSS Cascade 5 | `@layer` blocks have their contents parsed, and the ordering — the entire point — is discarded, so a layered sheet competes purely on specificity |
| CSS Color Adjustment 1 | Nothing |
| CSS Conditional 4 | Nothing. No `@container` |

## 3. Fairly stable, limited implementation experience

| Specification | Engine |
|---|---|
| CSS Display 3 | Partial: `none`, `block`, `flow-root`, `inline`, `inline-block`, `list-item` and the table values. `contents` wrongly generates a box, `inline-table` is not inline, and an unknown value falls back to `inline` rather than `block`. No two-value syntax |
| CSS Text 3 | Partial: `text-align`, `text-align-last`, `text-indent`, `text-transform`, `letter-spacing`, `word-spacing`, `tab-size` as a count of spaces or a length, and `word-break` and `overflow-wrap`, which break inside a word — `break-all` to fill the line it is on, `break-word` only once the word would not fit on a line of its own. `white-space` is stored as the two things it is a shorthand for, `white-space-collapse` and `text-wrap-mode`, so all five of its values are distinct and either longhand can be set on its own; `pre-line` keeps newlines while collapsing runs of spaces. `justify` renders as left, and `break-spaces` as `pre-wrap`, since neither engine breaks inside a run of preserved spaces. A tab expands to whole spaces rather than advancing to a tab stop. No `hyphens`, `line-break` or `text-wrap-style` |
| CSS Text Decoration 3 | Substantially: all three lines — `underline`, `overline` and `line-through` — with `text-decoration-color`, `text-decoration-style` in all five values (`solid`, `double`, `dotted`, `dashed` and a `wavy` drawn as stepped segments, since the canvas has no curve), `text-decoration-thickness` and `text-underline-offset`. `text-shadow` casts offset and blurred copies of the text and its decorations, the blur approximated by repeated draws at a fraction of the alpha as `box-shadow`'s is. The property is not inherited; it propagates to descendant boxes for painting, and its colour, style, thickness and offset propagate with it, so a decoration crossing a differently coloured descendant keeps the colour of the box that asked for it. Where two ancestors decorate the same text differently only the nearer one's appearance survives, because one set of fields cannot hold two answers. No `text-decoration-skip-ink`, no `text-emphasis` and no `text-underline-position` |
| CSS Box Alignment 3 | Only what Flexible Box 1 uses: `justify-content`, `align-items`, `align-self`, `align-content` and the `gap` family, on a flex container. Nothing on a block or a table, no `justify-items` or `justify-self`, and no `safe`/`unsafe` overflow keywords |
| CSS Writing Modes 4, Fragmentation 3, Shapes 1, Masking 1, Speech 1, View Transitions 1 | Nothing |

## 4. Rough interoperability

| Specification | Engine |
|---|---|
| CSS Lists and Counters 3 | Partial: `list-style-type` and markers in the bullet, decimal, alphabetic and roman styles, and the `<ol type>` attribute the standard maps to it. No `list-style-position`, no `list-style-image` |
| CSS Logical Properties 1 | Partial: `inline-size`, `block-size`, and the inline and block margin and padding aliases — all assuming left-to-right horizontal. `padding-block-start` and `padding-block-end` are not aliased |
| CSS Box Sizing 3 | `box-sizing` works, so a declared width or height can be the border box, and `max-height` is honoured rather than inert. No intrinsic keywords (`min-content`, `fit-content`) |
| CSS Positioned Layout 3 | CSS2's positioning is implemented (above). Nothing this level adds: no stacking contexts beyond painting positioned siblings in z-index order, no `inset` shorthand, no `sticky` behaviour — it computes as `relative` |
| Selectors 4 | Nothing beyond Level 3, and the five selectors the measurement still fails are all from here: `:is()`, `:where()`, `:has()`, a selector list inside `:not()`, and the attribute case-sensitivity flag, which is parsed and thrown away |
| CSS Color 5 | Nothing. No `color-mix()`, no relative colour syntax |
| CSS Transitions 1, Animations 1, Transforms 2, Motion Path 1, Will Change 1, Filter Effects 1, Fonts 4, Nesting 1, Containment 2, Scroll Anchoring 1 | Nothing. `@keyframes` blocks are skipped |
| CSSOM, CSSOM View, Geometry 1, Font Loading 3, Web Animations 1, Resize Observer 1 | Out of scope permanently: these are script interfaces, and there is no JavaScript engine (todo.md, "Deliberate non-work") |

## What this changes about the plan

**The snapshot's classification and this project's priorities do not
agree, and the classification wins on two counts.** Custom properties
with `calc()`, flexbox, and CSS Images are in the official definition of
CSS, not in some forward-looking tier: an engine missing them is missing
stable CSS, not modern CSS. Conversely `:is()`, `:where()`, `:has()` and
`@layer` ordering sit in the two lowest classes, so they are further
down the list than their prominence suggests.

**Positioning is official-definition work too**, through CSS2 §9.3
rather than through Positioned Layout 3. So are floats, `overflow`
clipping and generated content. The four largest holes in the engine are
all CSS2 chapters.

**The cascade bugs are fixed.** Specificity is compared as a triple,
importance inverts the origin order, `inherit` takes the parent's value,
`@supports` evaluates its condition, `text-decoration` and `opacity` no
longer inherit, `rem` and `vh` resolve against the real root font size
and viewport, and an unparseable selector drops its whole rule. What
remains of Cascade 4 is `revert` and `all`.

**A corpus is still the missing instrument.** The HTML parser went from
20% to 93% because someone else's tests said what was wrong; `css/` in
web-platform-tests is the equivalent, and the open question is how much
of it runs without script.
